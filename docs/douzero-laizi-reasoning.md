# 结论：基于 DouZero 能不能判断赖子怎么出？

**能。** 但有明确前提和边界，下面是实测证据。

---

## 一、核心结论

**能判断「赖子当什么牌最好」，不能判断「该不该留赖子」——后者需要搜索。**

| 能力 | 能否 | 依据 |
|---|---|---|
| 判断赖子当哪个点数最优 | ✅ 能 | 实测：单张赖子 6 种用法，打分 0.9319–0.9653，模型能挑出最优 |
| 判断用赖子 vs 不用赖子 | ✅ 能 | 实测：凑炸弹 0.7951 vs 只用对子 0.7061 |
| 判断赖子凑成什么牌型 | ✅ 能 | 实测：224 个合法动作全部打分，排序有区分度 |
| 判断「这张赖子该不该现在用掉」 | ⚠️ 近似 | DouZero 是单步价值网络，不是搜索。要精确需蒙特卡洛（PC 版有 `ddz_search.py`，手机端未移植） |

---

## 二、原理：为什么能

DouZero 没训练过赖子，所以直接喂赖子牌值等于喂了未见过的输入。做法是**具体化（concretization）**：

```
physical  9 + 赖子(7)          ← 实际打出的牌
concrete  [9, 9] 或 [9, A]     ← 赖子替换成某个真实点数，喂给经典模型
```

模型在 concrete 上打分，等价于问「如果我打的是这张具体的牌，价值多少」。

**关键**：同一手 physical 可以有多套 concrete，模型对它们的打分**不同** —— 这就产生了「赖子该怎么用」的判断力。

---

## 三、实测数据

### 实验 A：同一手牌，不同具体化，打分确实不同

局面共 224 个合法动作。找到 10 组「同一 physical、多种 concrete」：

```
physical [4,7,17,17,17,17]（1 张赖子）
  赖子当 4 → 0.893364
  赖子当 7 → 0.826168
  跨度 0.067196

physical [3,7,17,17,17,17]
  赖子当 3 → 0.881768
  赖子当 7 → 0.808482
  跨度 0.073286

10 组全部打分不同，最大跨度 0.924269
```

**结论：模型确实在区分赖子的用途，不是无差别打分。**

### 实验 B：单张赖子当 6 个不同点数

```
赖子当 6 → 0.965269   ← 最优
赖子当 4 → 0.957704
赖子当 5 → 0.955697
赖子当 3 → 0.952374
赖子当 7 → 0.944955
赖子当 8 → 0.931903
```

模型挑出「当 6」最优（手上有 5 6 8，当 6 能配合成顺子/连对）。

### 实验 C：凑炸弹 vs 只出对子

```
3 3 3 + 赖子 → 炸弹 3   打分 0.795097
只用对 3（留赖子）       打分 0.706079
```

### 实验 D：赖子当不同对子

```
赖子当 10 → 0.904356   ← 最优
赖子当 Q  → 0.899852
赖子当 J  → 0.888708
赖子当 A  → 0.872315
赖子当 K  → 0.852621
赖子当 7  → 0.771322   ← 当自己反而较差
赖子当 3  → 0.746336
...
```

**注意**：赖子当「自己」（7）打分偏低 —— 因为手上有 9 9、10 J Q K A，赖子当 7 帮不上牌型。模型捕捉到了这一点。

## 四、边界与局限

### 1. 不是「重新训练」，是「具体化 + 复用」

DouZero 没见过赖子。我们只是把赖子替换成具体牌后套用经典模型。
**打分是近似的**，尤其在「赖子该留还是该用」这类需要跨步推理的决策上。

### 2. 单步价值 ≠ 全局最优

DouZero 输出的是**当前局面的价值估计**，不是搜索后的最优着。
PC 版 `ddz_search.py` 用蒙特卡洛仿真（采样未知手牌 → 打到终局 → 统计胜率）能显著改善，
**但那个模块没有移植到手机端**（算力与耗时考虑）。

手机端当前行为：对每个合法动作打分，取最高。

### 3. 具体化的歧义

同一手牌可能有多套 concrete 都合法（如 `9+赖子` 可当对 9、当对 A、当对 2…）。
当前做法：**全部枚举并逐个打分**，取最优。这保证了不漏招。

### 4. 有真牌时不浪费赖子

实测发现：若某点数已有真牌，引擎优先用真牌。
这是**正确行为**（赖子稀缺），不是 bug。

```
PASS  赖子可凑成多种对子

PASS  经典模式推荐不变
```

全量回归：**278 用例 / 14 步骤，全部通过。**

## 六、本轮顺带修掉的 3 个真实 bug

| bug | 现象 | 影响 |
|---|---|---|
| `concretize` 无提示时产不出合法牌型 | `[7,9]` → `[3,9]`（不是对子） | 具体化结果非法 |
| 赖子点数被排除在替代候选外 | 12 张顺子含 1 张赖子被判非法 | **合法牌型被拒** |
| 赖子被当成大小王 | `[7,20]` → `[20,20]` | 违反 `laiziCanBeJoker=false` 默认规则 |

第三个是 `materialize()` 里没有对王做守卫 —— 现在改为「王不够就直接放弃该组合」。

## 七、如果要更准（未做）

1. **移植蒙特卡洛搜索到手机** —— PC 版 `ddz_search.py` 已有实现，
   但需评估手机算力（当前单步推理约 87 ms，仿真 200 次会到秒级）
2. **赖子专用模型** —— 需自行训练，DouZero 无赖子训练数据
3. **启发式补强** —— 如「赖子优先留给炸弹/关键牌」的规则层，与模型打分加权融合
