# 提示词优化：赖子玩法 + 免逐张输入

> 原始表述：
> 「赖子的玩法我也要.还有就是你要考虑到我要是每次开局一个个输入很麻烦.」
>
> 问题诊断：这句话里混了两个独立目标（**玩法扩展** / **输入体验**），
> 没有说明规则口径、没有验收标准、没有约束边界，直接执行会返工。

---

## 一、归一化

| 维度 | 内容 |
|---|---|
| **对象** | 手机端斗地主助手（`android-offline`，纯离线 DouZero 移植版） |
| **动作 A** | 增加「赖子」玩法（万能牌） |
| **动作 B** | 消除每次开局逐张输入手牌的重复劳动 |
| **产出物** | 可安装 APK + 规则说明 + 回归测试证据 |

---

## 二、优化后的提示词（可直接复用）

```text
目标：在手机端斗地主助手里加「赖子」玩法，并让开局录入不再逐张敲。

【A. 赖子玩法】
A1 规则口径（默认按湖北赖子斗地主，逐条列出并在交付里标注假设）：
   - 翻一张牌定赖子点数；赖子可代替除大小王外的任意牌
   - 赖子可单独出（视为任意单张）
   - 软炸（含赖子凑成）< 硬炸（天然四张）< 王炸
   - 提供开关：赖子能否当王、能否单独出
A2 必须有「经典模式 / 赖子模式」切换，切回经典时行为与现在逐位一致
A3 赖子模式下推荐要能用现有 DouZero 模型：
   - 做法：把赖子展开为具体牌的若干实现，用模型逐个打分取最优
   - 明确标注这是「基于经典模型的近似」，不是重新训练
A4 记牌器、撤销、候选列表在赖子模式下同样可用

【B. 输入体验】
B1 手牌与出牌都改成「点选牌面」录入，不再要求打字
B2 点选器要能表达重复张数（同一牌面点多次），并实时显示已选
B3 保存常用手牌为预设，支持一键回填
B4 保留最近 N 局手牌历史，可一键复用
B5 保留键盘输入作为备选路径，两种方式结果必须一致

【C. 约束】
C1 仍然纯离线、不联网、不依赖电脑
C2 不引入第三方依赖
C3 经典模式的行为不得回归（原有测试必须全绿）
C4 改动限定在 android-offline/ 与 tools/，不动 PC 端脚本的对外行为

【D. 验收】
D1 新增 JVM 测试覆盖：赖子牌型生成、赖子合法性、输入解析一致性
D2 原有 115 个用例仍全通过
D3 一键回归脚本跑完 8/8 步骤
D4 产出 APK 并核验模型内置、无测试类泄漏
D5 说明哪些是实测、哪些是未验证（无真机则明确标注）
```

---

## 三、执行顺序

```text
1. 规则层   GameRules（经典/赖子）+ 赖子合法性判定
2. 引擎层   赖子展开 → 复用 DouZero 打分；开关与经典模式隔离
3. 输入层   CardPickerView（点选）+ 预设/历史持久化
4. 测试层   JVM 用例（赖子 + 输入），回归原有 115 例
5. 交付     APK + 规则假设说明 + 实测/未验证边界
```

## 四、风险与对策

| 风险 | 对策 |
|---|---|
| 赖子展开组合爆炸 | 按「手牌内点数 → 上家牌点数 → 其余」优先级枚举并设上限 |
| DouZero 未训练过赖子，推荐可能偏 | 显式标注为近似；展开后按具体牌打分，保证规则内合法 |
| 改动波及经典模式 | 规则分支收敛到 `GameRules`，经典路径零改动 |
| 点选器状态与文本解析不一致 | 两条路径共用同一份 `parseCards`，加一致性测试 |
